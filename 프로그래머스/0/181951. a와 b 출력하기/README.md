## 💡 학습 노트: a와 b 출력하기

### 1. 문제 핵심 요약
- **핵심 키워드**: `#fs_module`, `#Destructuring`, `#map`, `#Template_Literals`
- **문제의 본질**: 공백으로 구분된 문자열 입력을 받아 개별 숫자 변수로 변환하고, 지정된 형식(`a = 값`, `b = 값`)으로 출력하는 시스템 입출력의 기초.

### 2. 작동 원리 및 설계
- **데이터 흐름 (Flow)**:
  1. **데이터 유입**: `fs.readFileSync(0)`를 통해 표준 입력 스트림으로부터 데이터를 통째로 읽어옴 (`"4 5\n"`).
  2. **정제 (`.trim()`)**: 문자열 끝에 붙은 줄바꿈 문자(`\n`) 등 불필요한 공백을 제거함 (`"4 5"`).
  3. **분할 (`.split(' ')`)**: 공백을 기준으로 문자열을 조각내어 **문자열 배열**을 생성함 (`["4", "5"]`).
  
  4. **일괄 변환 (`.map(Number)`)**: 배열의 각 요소를 순회하며 `Number` 함수를 실행, 숫자형 배열로 변환함 (`[4, 5]`).
  
  5. **변수 바인딩**: **구조 분해 할당(Destructuring)**을 통해 배열의 각 요소를 변수 `a`와 `b`에 할당함.
  

### 3. 효율성 및 성능 분석
- **시간 복잡도**: $O(n)$ ($n$은 입력 문자열의 길이). 입력을 읽고 분할하고 변환하는 과정이 모두 정비례하게 실행됨.
- **성능 최적화 포인트**: 
  - `fs` 모듈을 사용하여 **시스템 콜** 방식으로 데이터를 가져옴으로써 `readline`의 이벤트 오버헤드를 줄임.
  - 전역 변수를 최소화하고 즉시 변수화하여 메모리 효율(GC)을 높임.

### 4. 시행착오 및 깨달은 점
- **오타와 디버깅**: `iuput`, `splie` 같은 사소한 오타가 `TypeError`를 유발함을 확인. 에러 메시지(`is not a function`)를 통해 객체의 상태와 메서드명을 대조하는 습관의 중요성을 깨달음.
- **배열 가공의 실수**: 이미 쪼개진 배열의 첫 번째 요소(`inputSplit[0]`)에 다시 `split`을 시도하여 `undefined`가 발생하는 논리적 오류를 경험함. 데이터의 상태(배열인지 문자열인지)를 항상 추적해야 함.
- **표준 출력**: `console.log` 내에서 `\n`(개행 문자)을 사용해 한 번의 호출로 여러 줄을 출력하는 효율적인 방식을 학습함.
